# Критичний огляд репозиторію ZorroBot

Дата огляду: 2026-10-22. Гілка: `claude/zorrobot-0001-5w2tkz` (ідентична `master`, останній коміт `1c32b15` від 2021-11-17).

## Що це

ZorroBot — заготовка Telegram-бота на Python (pyTelegramBotAPI), яка наразі лише повторює будь-яке текстове повідомлення назад користувачу (`app/app.py`, 20 рядків). У 2018 році це був бот, що через R-скрипт і пакет `wbstats` тягнув населення країни зі Світового банку й надсилав графік; у листопаді 2021 автор повністю зніс R-частину («библиотека в R перестала работать») і переналаштував репозиторій на зв'язку VS Code + Dev Container + Docker. Після цього пивоту корисної логіки в репо немає: є Dockerfile, два docker-compose, devcontainer і шаблон `config.json` з ключами для Telegram і Trello, але Trello ніде не використовується. Тестів, CI, ліцензії й документації з кроками запуску немає; README складається з двох речень.

## Що перевірено запуском

- `python3 -c "import json; json.load(open('app/config.json'))"` — падає з `JSONDecodeError: Illegal trailing comma` (підтверджено, Python 3.13).
- Встановлення `requirements.txt` у чистий venv — успішне; тягне pyTelegramBotAPI 4.37.1, pandas 3.1.0, openpyxl 3.1.5.
- Запуск `app/app.py` з валідним JSON і фіктивним токеном — код доходить до `bot.polling`; сам Telegram API з пісочниці недоступний (403 від проксі), тому поведінку при невалідному токені не перевірено.
- `inspect.signature(telebot.TeleBot.polling)` — параметр `none_stop` ще приймається, але позначений як застарілий; актуальна назва `non_stop`.
- Симуляція ситуації «файл `config/config.json` відсутній при `docker-compose up`» (Docker створює каталог замість файлу) — бот падає з `IsADirectoryError`.
- Збірка Docker-образу не перевірена: у пісочниці немає Docker-демона.
- Перегляд усієї історії git: файл `__config__.py` з 2018 року містив змінну `token`, але значення за формою не є справжнім токеном Telegram (плейсхолдер); рядків, схожих на реальний токен, в історії не знайдено.

## Питання власнику

- Чи є у проєкту мета після пивоту 2021 року: повернути функцію «населення країни зі Світового банку» вже на Python (pandas уже в залежностях), чи це просто шаблон для нових ботів?
- Для чого в шаблоні конфігу ключі Trello: інтеграцію планували, чи це залишок із іншого проєкту?
- Де реально лежить робочий `config/config.json` і чи запускався контейнер через `run.sh` після листопада 2021 року?
- Чи має бот працювати десь постійно (сервер, Raspberry Pi), чи лише локально під час розробки? Від цього залежить, чи варто вкладатися в compose/devcontainer.
- Чи є плани на вебхуки замість polling (потрібен публічний HTTPS)?

## Рекомендація

Мінімально оживити, але лише якщо є відповідь на перше питання вище; інакше архівувати як є. Аргумент: корисного коду в репозиторії фактично немає (20 рядків echo-бота), тож «переписувати» нічого, а архівувати заготовку, у якій витрачено час на Docker і Dev Container, шкода. Реанімація коштує близько години: виправити кому в JSON (п. 1), винести токен у змінні оточення й прибрати відстежуваний конфіг (п. 2–3), зафіксувати залежності й викинути невикористані (п. 4, 10), додати LICENSE, README з кроками запуску та один smoke-тест із CI (п. 5–7). Після цього репозиторій стане чесним шаблоном Telegram-бота, на який можна нарощувати функціонал. Якщо ж плану на функціонал немає, краще додати в README рядок «archived, заготовка 2021 року» і заархівувати, щоб не підтримувати мертве середовище.
